# 点赞按钮设计

## 范围

在首页左侧工作台标题区域增加一个面向公开访客的真实点赞控件。上线初始计数为 `276`；访客成功点赞后，总数加一，已点赞状态在该浏览器中保持一致。

## 界面与交互

- 控件与“使用说明”并列，位于“皖志愿”标题的操作区。
- 使用 Lucide 的 `Heart` 图标，未点赞时为描边，已点赞时为红色填充。
- 控件使用按钮语义、中文 `aria-label` 与悬停提示，键盘可触发。请求进行中禁用按钮，失败时显示简短提示并保持服务端确认的计数。
- 数字不受长文本或响应式布局影响；窄屏时随同标题操作区正常换行。

## 状态与数据

- PostgreSQL 保存全站计数与匿名访客投票记录。数据库迁移创建一个单行计数记录（初始值 `276`）及按 `reactionKey + visitorHash` 唯一的投票记录。
- `GET /api/likes` 返回当前计数和当前浏览器是否已点赞；`POST /api/likes` 在事务中写入投票记录、原子递增计数，并返回新的状态。重复点赞返回现有状态，不重复计数。
- 第一次访问由服务端设置随机的 `HttpOnly`、`Secure`、`SameSite=Lax` 匿名 Cookie；数据库只存其 SHA-256 哈希值，不存原始标识。
- 无登录体系。清除 Cookie、改用其他浏览器或网络仍可能再次点赞，因此这不是身份级的绝对唯一性保证。

## 防刷控制

- 写接口仅接受同源 `POST` 请求，拒绝无效请求体；不信任客户端传来的计数或访客标识。
- 以匿名访客标识与 IP 为维度限流，限制短时间内的重复写请求。限流状态使用 Vercel 可访问的 Redis 存储，避免无状态函数实例间失效。
- 数据库唯一约束是最终防线，即使并发请求穿过限流，也只能写入一次有效投票。
- 服务端记录异常限流命中，后续若出现明显自动化滥用，可加 Cloudflare Turnstile，不在本期默认增加验证码。
