# 推荐算法草案

## 原则

1. 先硬规则过滤，再做推荐排序。
2. 以位次为核心，不以分数为核心。
3. 第一版推荐单位是院校专业组。
4. 历史/物理科目轨道必须先匹配，再比较院校专业组位次。
5. 数据不足时标低置信度。
6. 推荐理由必须来自结构化数据。

## 第一版参考位次

```text
预测参考位次 =
  2025 最低位次 * 0.6
+ 2024 最低位次 * 0.4
+ 招生计划变化修正
+ 波动风险修正
```

如果只有一年数据，使用单年数据并标为低置信度。新增、拆分、合并或名称变化的专业组进入人工确认。

## 冲稳保分档

```text
rank_gap_ratio = (用户位次 - 预测参考位次) / 预测参考位次
```

| 档位 | 初始规则 |
| --- | --- |
| 冲 | 0% 到 +8% |
| 稳 | -12% 到 0% |
| 保 | -30% 到 -12% |
| 过保 | 小于 -30% |
| 高危 | 大于 +8% |

阈值需要用安徽 2024、2025 数据回测后修正。

## 默认志愿组合

| 档位 | 数量建议 |
| --- | --- |
| 冲 | 8-12 |
| 稳 | 20-25 |
| 保 | 8-12 |
| 过保 | 1-3 |

保底志愿必须在用户可接受范围内。如果保底不足，系统必须提示。

## 第 5 周实现状态

- 已新增 `POST /api/recommendations`，在第 4 周规则候选集基础上生成推荐列表。
- 已实现最近两年最低位次加权、招生计划变化修正和位次波动保守修正。
- 已实现冲、稳、保、过保、高危分档。
- 已实现风险偏好、城市偏好、专业偏好、排斥方向、学费预算和计划明细偏好评分。
- 已实现低置信度标记，覆盖历史数据不足、OCR 样例、招生计划样例、缺少计划明细和波动过大。
- 正式推荐默认要求有当年招生计划明细；OCR 历史投档样例只用于排查和解释，不默认进入正式推荐。

## 第 6 周展示状态

- 首页工作台已接入 `POST /api/recommendations`。
- 桌面端用推荐表格展示分档、位次模型、招生计划、风险标签和推荐理由。
- 手机端用推荐卡片展示核心推荐信息。
- 详情面板展示院校专业组历史位次、专业计划、风险标签和推荐解释。
- 第 6 周不进入志愿表编辑和保存方案。
