# 第六周数据一致性审计

## 背景

用户输入 `550` 分、位次 `70000` 时曾出现北京大学推荐结果。复核后确认，这不是单个算法阈值问题，而是安徽投档表中的院校代码存在跨年复用：同一 `college_code` 在不同年份可能对应不同学校。

## 全量审计结果

本次审计覆盖 `data/cleaned/anhui` 下已清洗 CSV：

| 数据表 | 行数 | 结果 |
| --- | ---: | --- |
| `score_segments.csv` | 1934 | 分数段位次区间校验通过 |
| `colleges.csv` | 51 | 院校名脏值校验通过 |
| `college_groups.csv` | 219 | 专业组键唯一，名称快照完整 |
| `enrollment_plans.csv` | 17 | 均能引用到专业组 |
| `admission_results.csv` | 216 | 均能引用到专业组 |
| `charter_rules.csv` | 0 | 当前无章程规则样本 |

发现并处理的风险：

- `college_code` 跨年对应不同院校名称：22 个代码。
- `province + batch + subject_track + college_code + group_code` 跨年对应不同院校名称：30 组。
- OCR 院校名脏值：1 条，`4北京第二外国语学院` 已修正为 `北京第二外国语学院`。
- 招生计划和投档结果孤儿引用：0 条。

典型代码复用案例：

| 代码 | 2024 样本 | 2025 样本 |
| --- | --- | --- |
| `1029` | 北京大学 | 北华大学 |
| `1032` | 北京电影学院 | 北京大学 |
| `1024` | 北方民族大学 | 北部湾大学 |
| `1030` | 北京大学医学部 | 北华航天工业学院 |

## 修复策略

1. `college_groups.csv` 保留每一行当年的 `college_name` 快照。
2. API 展示专业组时优先使用 `collegeNameSnapshot`，不再只依赖全局 `college.collegeName`。
3. 推荐历史投档匹配增加院校名称快照隔离，避免把同一代码组合下的不同院校混入同一历史依据。
4. 列表搜索加入 `collegeNameSnapshot`，保证按当年真实院校名可搜索。
5. CSV 校验增加院校名脏值检查，并对代码复用输出 warning。
6. `tests/week6-data-guard.ts` 固化北大/北华大学等关键样例和全量引用检查。

## 当前限制

现有 `college` 主表仍以 `college_code` 唯一建模，适合作为开发期基础表，但不能代表跨年的稳定院校身份。当前第六周已通过专业组名称快照规避推荐和展示错误；后续如进入正式生产数据阶段，建议引入年度院校身份表或院校别名表，把 `college_code + year/province/batch` 与真实院校实体拆开建模。
